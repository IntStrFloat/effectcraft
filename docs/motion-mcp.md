# Motion-design MCP этого форка

Цель — создавать собственные редактируемые сцены по описанию и проверять их реальным
рендером: текст, карточки, появления, акценты, переходы и их развитие во времени.
MCP расширяет существующее управление EffectCraft; низкоуровневые команды, свойства,
маски, формы, камеры и Render Queue остаются доступны.

> Этот форк — самостоятельный alpha-инструмент. Совместимость с `.aep`/`.aepx`, `.ffx`
> и Adobe SDK plug-ins (`.aex`, `.plugin`) не предоставляется. Собственный WebAssembly
> plug-in API — другой формат, описанный в [plugins.md](plugins.md).

## Собрать и подключить

Нужен Rust 1.95 или новее. Сборка не добавляет новые зависимости для motion MCP поверх
существующего workspace.

```sh
git clone https://github.com/IntStrFloat/effectcraft
cd effectcraft
cargo build --release -p effectcraft-cli
```

Укажи абсолютный путь к `target/release/effectcraft-cli` (`.exe` на Windows) в своём
stdio MCP-клиенте. Для Codex:

```sh
codex mcp add effectcraft -- /absolute/path/to/effectcraft-cli mcp --autosave \
  --automation-read-root /absolute/project \
  --automation-write-root /absolute/project
```

Каталоги должны существовать. Корни повторяемы; write-root также разрешает чтение.
При необходимости перезапусти MCP-подключение клиента. Не запускай сервер через
`cargo run` при каждом старте: заранее собранный бинарник избегает таймаута компиляции.

Без корней сохраняется обычный доступ сервера к файлам. С корнями прямые скрипты и
UI-действия ограничены; подробные правила в [mcp.md](mcp.md).

Для видимого приложения:

```sh
effectcraft --control 0
# Прочитай фактический порт из stdout приложения:
effectcraft-cli mcp --bridge PORT
```

Переиспользуй открытый экземпляр и его проект. Bridge не совмещается с `--autosave`:
приложение само управляет checkpoint. Headless по умолчанию работает на CPU; `--gpu`
подключает GPU compositor и требует доступного адаптера. Проверяй активный backend
через `get_capabilities`/`get_project`.

## Рабочий цикл

1. `get_motion_workflow` → `get_capabilities` → `get_project` → `get_comp`: инструкции,
   возможности текущего backend и состояние.
2. `motion_catalog` → `plan_motion`: назначение, характер, допущения и этапы.
3. `create_motion_scene`: новая редактируемая композиция; существующий проект сохраняется.
4. `get_layer`, `get_property`, `animate_layer`, `set_property`, `add_keyframe`, `add_effect`:
   адресная доработка. Эффекты и шрифты сначала найди через `list_effects`/`list_fonts`;
   цепочку применяй через `apply_effect_chain`.
5. `analyze_scene` → `render_storyboard` → `render_frame`: структура и реальные кадры разных фаз.
6. `save_project` → native Render Queue → проверка файла и повторное открытие проекта.

Все шесть рецептов дают стартовую **2D-сцену**. Возможности всего редактора шире.
Сложный переход через
маску, трекинг, ротоскопирование или пространство строится дальнейшими native-командами.
Не следует объявлять готовым такой переход по одному наличию стартовой карточки.

Сначала смотри актуальную JSON Schema в `tools/list`: она определяет обязательные поля,
допустимые значения и лимиты текущей версии. Описание языка и нюансы запроса интерпретирует
модель MCP-клиента, а не скрытая модель внутри сервера.

## Новые инструменты

| Инструмент | Назначение |
|---|---|
| `get_motion_workflow` | Постоянная инструкция полного цикла работы с этим форком. |
| `get_capabilities` | Реальный backend, доступные native-возможности и ограничения форматов/плагинов. |
| `list_plugins` | Собственные WebAssembly effect plug-ins; совместимость с Adobe SDK не подразумевается. |
| `load_effect_plugin` | Загрузка собственного API-v1 `.wasm`/`.wat` по абсолютному пути с обычной проверкой read-root. |
| `motion_catalog` | Стартовые рецепты, характеры движения и их область применения. |
| `plan_motion` | План и допущения без изменения проекта. |
| `create_motion_scene` | Новая сцена из native-слоёв и редактируемых свойств. |
| `animate_layer` | Анимация заданного слоя с явным временем композиции. |
| `apply_effect_chain` | Цепочка эффектов заданного слоя в режиме `append` или `replace`. |
| `render_storyboard` | Изображения нескольких фаз, собранные из реального рендера. |
| `analyze_scene` | Структурные предупреждения композиции; художественную оценку делает агент по кадрам. |

Стартовые назначения: `title`, `caption`, `card`, `screen`, `impact`, `glitch`.
В `apply_effect_chain` явно передавай `comp`, `layer`, `mode` и массив
`effects: [{effect, values?, enabled?}]`. Метаданные эффектов бери из `list_effects`.
`replace` удаляет прежние эффекты целевого слоя с их параметрами/ключами; `append`
сохраняет их и добавляет новую цепочку. Проверяй выбранный режим до выполнения.
Литеральные строки вида `$1`/`$1.effect` совпадают с синтаксисом ссылок native batch:
в атомарных помощниках они отклоняются до правки. Для такого точного текста используй
прямой `set_property`/native text-команду после построения сцены. Имена целей помощник
разрешает в числовые id, поэтому композиции и слои с такими именами остаются доступны.
Для импортированного материала передавай существующий `source_item`; сначала импортируй
файл через `execute_command` → `file.import`, чтобы он прошёл обычные проверки доступа.
Кадры, слои и свойства сохраняются в обычном `.ecproj` и доступны базовым инструментам.

## Примеры запросов

> Сделай мягкое появление заголовка на три секунды: короткий вход, время прочитать,
> спокойный уход. Верни кадры начала, удержания и завершения.
>
> Из импортированного видео сделай карточку, которая раскрывается в полный кадр.
> Сохрани узнаваемую область и проверь крайние положения.
>
> Усиль акцент в этой композиции, сохрани остальные слои. Сначала покажи план,
> после правки сравни несколько кадров с исходным вариантом.

У нового проекта после создания нужно сохранять возвращённые `comp`/`layer` id, а не
угадывать номера слоёв. Путь свойства бери из `get_layer`; ключи низкого уровня по умолчанию
используют layer time. Для таймлайна явно передавай `timeBase: "comp"`.

## Проверка результата и ограничения

- Статический кадр не проверяет движение. Смотри вход, удержание, выход и конкретный шов.
- Storyboard принимает `comp?`, `times?` (1–12 времён композиции), `max_side?` (64–960),
  `columns?` (1–4), `transparent?`. Длительность ограничивается выбранными кадрами;
  общий диапазон native Render Queue остаётся самостоятельным.
- Alpha проверяется отдельно: чёрный фон в просмотрщике не доказывает прозрачность.
- Аудит структуры не подтверждает визуальную идентичность After Effects или качество
  каждого из встроенных эффектов. Отсутствие предупреждения не заменяет просмотр.
- Рендеринг искажённого исходника, шрифта или маски может зависеть от текущей сборки,
  renderer и установленных моделей. Называй обнаруженные ограничения явно.
- Экспорт надо проверить по фактическому файлу: размеры, FPS, длительность, кадры, alpha
  и при необходимости звук. Данные очереди сами по себе не являются экспортированным видео.
- Сохрани редактируемый проект и повторно открой его в отдельной сессии, проверив источники
  и контрольные кадры. Локальный renderer не сертифицирует производственную надёжность
  всех платформ и всех чужих плагинов.

Команды проверки разработки: `cargo test -p effectcraft-automation` и полный
`cargo xtask ci`. Фактические результаты запуска следует указывать отдельно от этих команд.
Постоянная инструкция агента: [AGENT_MOTION_WORKFLOW.md](AGENT_MOTION_WORKFLOW.md).
